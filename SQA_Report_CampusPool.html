1. Executive Summary

This report presents the results of an individual Software Quality Assurance campaign against CampusPool (https://carpool.33.jugaar.ai), a university carpool platform for Karachi students. Testing covered the live production deployment using black-box, grey-box and white-box approaches, supported by source-code review and automated evidence capture.

84 quality findings were documented: 1 Critical · 24 High · 52 Medium · 7 Low. The campaign applied 133 distinct testing techniques (requirement: 100+), including functional, UI/UX, accessibility, responsiveness, cross-browser, performance, API, security, reliability and exploratory methods. Findings follow a standard defect-report template: ID, Severity/Priority, Environment, Steps, Oracle, Actual, Evidence, Impact — with techniques listed on each finding.

Priority themes: simulated payment gateway shown as success · fake student verification · public driver phone exposure · ride cancel without booking cascade · seat-inventory corruption on double-cancel · passenger self-confirm · ignored search filters · database wipe on restart · stored XSS / encoding pollution · mock-only marketing pages.

Appendix E — Methodology

E.1 Approach

  1. Reconnaissance: Mapped stack, routes, API surface, deploy topology, demo accounts.
  2. Test design: Selected 133 techniques from ISTQB/ISO 25010 practice; designed partitions and boundary values for seats, price, ratings, passwords, limits.
  3. Execution — API/security: Scripted HTTP campaigns on production API; captured status codes and JSON evidence.
  4. Execution — UI: Playwright journeys (register/login/search/ride/booking/profile/mock pages); screenshots; responsive matrix; a11y audit; cross-browser renders.
  5. Execution — white-box: Reviewed controllers/models/middleware/configs to confirm root causes.
  6. Curation: Filtered false positives; assigned severity/priority/oracle/impact.
  7. Reporting: Assembled this A4 print-ready report.
